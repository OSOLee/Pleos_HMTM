# HMTM 앱 화면 설계 (v0.1)

> **일부 내용은 구현과 다를 수 있음, 최신은 [README](../README.md).** 개발 중에 쓴 설계 문서로, "차량 기록은 참고 자료" 결정 이전 내용이 섞여 있다. 본문에 나오는 `*-notes.md`, `api-current.md`, devlog, CLAUDE.md는 내부 작업 기록이라 이 저장소에 넣지 않았다.

원본 시안: claude.ai 디자인 캔버스 "HMTM 앱 화면 설계" (화면 6개).
이 문서는 시안을 Compose로 옮길 때 기준이 되는 명세다. 시안과 다르게 구현해야 하면
`docs/app-bb-notes.md`에 이유를 남긴다.

## 1. 공통

2026-11-10부터 `docs/pleos-design-rules.md`(우선)와 `docs/pleos-tokens.json`을 따른다. 이 절은 코드에 옮긴 값의 요약이고, 가이드와 다르게 한 것은 `docs/app-bb-notes.md` 13절.
코드: `ui/theme/Theme.kt`(색·글자·치수), `ui/components/Components.kt`(버튼·배지·팝업·토스트), `ui/Layout.kt`(창 모양).

### 창 크기와 배치
- Pleos 앱 영역(에뮬레이터 1682 × 1210dp). 왼쪽 계기판·위 상태바·아래 공조 바는 시스템 영역이라 그리지 않는다.
- **배치는 기기 방향이 아니라 창 크기로 고른다**: 폭 ≥ 높이이고 폭 ≥ 1000dp면 가로 배치(`LocalWide = true`), 아니면 세로 배치. 1:1 분할 창(약 840 × 1210dp)이 세로 배치다.
- 바깥 여백 40dp, 카드 사이 24dp, 카드 안 여백 32dp, 카드 둥글기 16dp, 카드 안 행 12dp.

### 색 (라이트·다크, 시스템 야간 모드를 따름)
`pleos-tokens.json`의 `#RRGGBBAA`를 Compose `#AARRGGBB`로 옮겼다. 다크 카드는 바탕과 같은 색이라 1dp 구분선 테두리, 라이트 카드는 그림자.

| 이름 | 토큰 | 쓰임 |
| --- | --- | --- |
| background / surface / surfaceHigh / popup | background·surface 계열 | 화면 바탕 / 카드 / 카드 안 행·보조 버튼 / 팝업 |
| text / textSecondary / textTertiary | text primary·secondary·tertiary | 본문 / 보조 / 덜 중요한 글자 |
| filled · onFilled | button/filled | **주 버튼**(분석 시작, 다음, 질문 답하기), 토스트 |
| basic | button/basic | 보조 버튼 |
| accent · accentText | informative/positive | 강조에만: 내 차 숫자·비율 막대, 진행, 고른 보기 테두리, 바뀐 비율 |
| active | informative/active | "기록 중" 점, 지시등 띠, 완료 체크 (글자에는 안 씀) |
| danger · dangerText | regulation/red | 삭제 아이콘·점선 / 삭제 버튼 글자(대비 조정 색) |

| --- | --- | --- |
| vehicle (내 차 종류) | 차량 정보 | 파랑 |

### 배지 두 방식 (2026-11-13, 고르는 중)
`Components.kt`의 상수 `BADGE_STYLE` 하나로 앱 전체를 바꾼다 (기본 `BadgeStyle.Color`). 화면 하나만 바꿀 때는 `LocalBadgeStyle`.

| | 색 방식 (Color, 지금) | 아이콘 방식 (Icon) |
| --- | --- | --- |
| 바탕 | 갈래마다 다른 색 (위 표) | 모두 `surfaceHigh` 회색 |
| 글자 | 갈래 글자색 | `textSecondary` (대비 시험에 있는 짝) |
| 구분 | 색 | 아이콘 24dp: 차량 기록·차량 정보 = 차, 영상 = 카메라, 내 답변 = 사람, 가정·추정 = 물음표 |
| 효과 배지 | 주황 / 초록 / 파랑 | ↑ 내 과실 증가 / ↓ 감소 / ⇄ 기준이 바뀜, 반영 안 함 = 물음표 |

캡처: `docs/images/ui-final-badge-color.png` · `ui-final-badge-icon.png` (같은 사건 결과 화면).

### 버튼
- 크기: 큰 100dp(분석 시작, 다음, 결과 보기), 중간 80dp, 작은 64dp. 아이콘 버튼 80 × 80 원형은 **뒤로에만** (나머지는 글자가 있는 버튼).
- 상태: 눌림(Pressed 색), 꺼짐(Disabled 색), 로딩(글자 대신 진행 원). 서버를 부르는 버튼(답 보내기, 삭제 확인, 모든 기록 삭제, 더 보기·다시 불러오기, 영상 고르기 검사)은 응답까지 로딩.
- 모든 버튼·보기·스위치는 햅틱(`VIRTUAL_KEY`), 물결(ripple) 없음.
- 확인은 시스템 팝업 규격(폭 808dp, 여백 48dp, 버튼 둘), 짧은 알림은 화면 아래 토스트(3초).

### 움직임
- 진행 표시(분석 중 막대·원, 버튼 로딩)만 움직인다. 화면 전환·펼치기 애니메이션, 흐르는 글자 없음.

### 대비
- 모든 글자·아이콘 색 짝 4.5:1 이상, 라이트·다크 모두 (`ContrastTest`, 반투명 색은 실제 바탕에 섞어 계산).

### 주행 중
- 홈 외의 화면은 정차 중 사용 전제. 주행 중이면 "영상 선택"과 "분석 시작"·질문 보기를 끄고 "정차 후 사용할 수 있어요"를 표시한다.

### 문구
- 화면 문구는 `res/values/strings.xml`. 서버가 보내는 문장(근거, 질문, 차량 기록 요약·규칙 문장, 판정 안내)은 서버 문구 그대로.
- 알림: 한 줄 "사고 분석용 차량 기록 중" (채널 "차량 기록").

## 2. 화면

### 2.1 홈
- 위: 제목 "사고 기록" + 오른쪽 "지난 분석" 버튼(흰 알약 모양, 시계 아이콘).
- 가운데 2열 카드
  - 왼쪽 "기록 상태": 초록 점 + "기록 중"(26sp, success), 설명 "시동을 켜면 자동으로 기록해요. 사고가 나면 블랙박스 영상과 함께 분석할 수 있어요."
    아래 구분선으로 나눈 3행: 보관 기간 / 최근 72시간, 기록 항목 / 속도 · 기어 · 방향지시등 · 브레이크, 저장 위치 / 이 차량 안에만.
    기록이 꺼져 있으면 회색 점 + "기록 꺼짐".
  - 오른쪽 "사고 의심 순간": 급제동 북마크 목록. 행마다 경고 아이콘(#9A4A00) + "오늘 14:32" + "급제동 · 62 → 8 km/h". 없으면 경고 아이콘 + "급제동이 있으면 여기에 표시돼요". 홈에는 4개까지(나머지는 지난 분석).
  - 두 카드 높이는 내용에 맞춘다(빈 공간으로 늘리지 않음).
- 아래: 주 버튼(button/filled) 큰 버튼 "블랙박스 영상으로 사고 분석" / "정차 중에만 사용할 수 있어요" + 오른쪽 화살표.

### 2.2 영상 가져오기
- 뒤로 + 제목 "영상 가져오기".
- 왼쪽 카드: 번호 원(1, 2) 단계 안내
  1. "메모리 카드를 USB 포트에 연결" / "블랙박스 메모리 카드를 리더기에 넣어 차량 USB 포트에 꽂아주세요"
  2. "사고 장면 영상 선택" / "앞 카메라 영상을 골라주세요. 사고 순간이 담긴 1분 영상이면 충분해요"
  아래 테두리 버튼 "USB에서 영상 선택"(72dp, 강조색 테두리·글자).
- 오른쪽 카드 "선택한 영상"
  - 썸네일(어두운 사각형 + 재생 아이콘) + 파일 이름 + "길이 1분 00초 · 촬영 시작 14:32:05"
  - "차량 기록" 행: 기록 구간 + 시각 맞추기 배지 (coarse: "시각 대략 일치" 초록 / none: "시각 확인 안 됨" 가정색 / 기록 없음: "차량 기록 없음" 회색)
  - 안내: "원본 영상은 분석이 끝나면 서버에서 바로 지워요. 이 USB에는 그대로 남아 있어요."
  - 주 버튼 "분석 시작". 영상을 고르기 전에는 비활성.

### 2.3 분석 중
- 가운데 카드 하나(폭 640dp): 제목 "분석하고 있어요"(고른 사고 순간으로 다시 분석이면 "고른 순간으로 다시 분석하고 있어요"), 보조 "몇 분 걸릴 수 있어요"(실제 서버는 CPU).
- 진행 막대(12dp). 분석 단계에서 서버 `progress`가 0이면 값 없는 막대(단계 표시만), 있으면 그 값과 단계 글자 옆 "· 40%".
- 4단계 목록: 영상 올리기 / 상대 차와 신호 분석 / 차량 기록 맞춰 보기 / 과실비율 판정.
  상태별 표시: 완료(초록 체크 원 + "완료"), 진행 중(강조색 테두리 원 + 굵은 글자 + "진행 중"), 대기(회색 테두리 원 + 보조색 + "대기").
- 아래 안내: "출발해도 분석은 계속돼요. 결과는 정차 후 확인하세요".
- 실패 시: 같은 카드에 오류 메시지와 "다시 시도" 버튼.

### 2.4 질문 (2부)
- 위: "질문 1 / 2" + 질문 문장(30sp). (2026-11-10: "차량 기록으로 N개 확인됨" 배지는 뺐다. 차량 기록은 질문에 답하지 않는다, design-blackbox 4.4)
- 왼쪽 카드: 질문에 맞는 그림(교차로 위에서 본 모습, 내 차는 강조색으로 아래에서 진입).
  - 그림 아래: 추정 근거 문장(`guess_evidence`), 그 아래 **차량 기록 참고 상자**(질문에 `vehicle_hint`가 있을 때, 차량 기록 색 바탕):
    "차량 기록: 안 켬"(추정이면 " (추정)") 굵게 → 규칙 문장(`text`) → 한 줄 안내.
    안내는 시각을 대략만 맞춰 반영하지 않은 값이면 서버 `reason_text`, 아니면 "참고용이에요. 결과는 고른 답으로 정해요".
  - 차량 기록 값은 보기에 미리 고르거나 "추정" 배지를 붙이지 않는다 (판정은 사용자 답 기준).
- 오른쪽: 2×2 큰 선택 버튼(최소 96dp). 선택되면 강조색 3dp 테두리 + #E7EEFF 바탕.
  보기는 서버 질문의 보기를 그대로 쓰되, 방향은 내 차 기준(왼쪽에서/오른쪽에서/맞은편에서/뒤에서).
- 아래: 글자 버튼 "잘 모르겠어요", 주 버튼 "다음".
- 화면 순서(2026-11-11): 서버 `remaining`(필수) 뒤에 선택 질문(`questions` 중 `optional`, 특수 상황·운전자 요인)을 붙인다. 여러 개 고르기·묶음 화면은 2.8.
- **이어지는 질문**(2026-11-11): 답을 보낸 뒤 서버 `remaining`에 이번에 묻지 않은 질문이 새로 생기면(예: 운전자 요인에서 과속 → "내 차가 제한속도를 지켰다면 사고를 피할 수 있었나요?",
  신호등 "있음" → 신호 질문) 결과로 가지 않고 그 질문을 바로 잇는다. 위 줄은 "이어지는 질문 1 / N". 새 질문이 없으면 결과 화면.
  "상대가 OO가 아니었나요?"로 연 질문은 잇지 않는다(상대 종류를 바꾸면 질문 장 전체가 바뀌어 결과에서 다시 시작).
- 답변 고치기: 묶을 질문은 한 화면으로 모으고, 과속 인과관계 질문은 그 당사자 운전자 요인 바로 뒤. 운전자 요인에서 과속을 빼면 인과관계 질문은 숨기고 그 답도 보내지 않는다.
- 주행 중: 모든 보기·체크 칸·"다음"·"건너뛰기"가 꺼지고 "정차 후 사용할 수 있어요" (1절 주행 중).

  가정(default) 항목에는 "다르면 결과가 바뀔 수 있어요"를 덧붙인다.
- 아래 버튼 3개(60dp): 영상 다시 보기(기기의 원본 재생), 답변 고치기, 사건 삭제(위험색). 버튼 최소 폭 300dp라 1:1 분할 창에서는 2 + 1줄.

  가로 배치에서는 왼쪽 열 과실비율 카드 아래에 둔다 (2026-11-10 Pleos 개편 전에는 근거 카드 위).

  - 결과를 바꾸는 기록(`vehicle_effects` 중 `applied: true`)이 있으면: 바뀐 비율 `result_with_vehicle.fault_display.text`("내 차 70 : 상대 30")를 30sp 차량 기록 색으로,
    아래 행마다 배지("내 차 과실 +10" / "내 차 과실 −10" / 도표가 바뀌면 "적용 기준이 바뀜") + 서버 요약 문장("내 차가 방향지시등을 켜지 않았어요") + 규칙 문장(작게). 행은 3개까지.

    행 배지 "반영 안 함"(가정 색) + 요약 문장 + "시각이 정확히 맞으면 내 차 70 : 상대 30".

  - 기본 판정(과실비율 카드)은 바꾸지 않는다. 기록을 제출·내보내는 버튼은 없다.
- **"확인해 주세요" 안내 카드** (2026-11-11, backend-gaps-notes). 과실비율 카드 바로 아래(가로·세로 모두). 행이 없으면 카드도 없다.
  - 행마다 가정 색 바탕(`assumedBg`/`assumedFg`) 굵은 제목 + 서버 문장 그대로.
  - `data_quality.clock_warnings`의 `kind: video_clock` → "영상 촬영 시각을 확인해 주세요", `vehicle_clock` → "차량 기록 시각을 확인해 주세요" + `message`("블랙박스 시계가 3일 전으로 맞춰져 있어요…").
  - `sync_reason`이 `vehicle_clock_mismatch`·`vehicle_record_not_covering`이면(차량 기록을 올렸지만 못 씀) "차량 기록을 쓰지 않았어요" + `sync_reason_text`.
    차량 기록을 안 올린 사건(`no_vehicle_record`)은 안내하지 않는다.

### 2.7 기록 보기 (2026-11-10)
결과 화면 차량 기록 카드의 "기록 보기". 서버 `vehicle_timeline`만으로 그린다 (원본 기록을 다시 읽지 않음).
- 뒤로 + 제목 "차량 기록" + 보조 "부딪히기 15초 전 ~ 5초 뒤 · 참고 자료예요". 뒤로 가면 결과 화면.
- 가로: 왼쪽 3칸 그래프 카드, 오른쪽 2칸 요약 카드. 세로: 그래프(높이 520dp) 아래 요약.
- 그래프 카드 "속도와 조작" + 범례 알약(속도 #1E5EE6 / 지시등 #0E7A45 / 브레이크 #C0392B). Compose Canvas로 그린다.
  - 가로: 충돌 기준 초, 5초 간격 눈금("−15초" … "0초" … "5초"). 세로: km/h, 최댓값을 10 단위로 올림(최소 20), 10(60 넘으면 20) 간격 가로선.
  - 속도 꺾은선 3dp. 기록이 없는 점(`null`)에서 끊고, `gaps` 구간은 회색 바탕.
  - 그 아래 띠 두 줄(36dp, 빈 띠에는 "켜지 않음"/"밟지 않음"): "지시등" 켜진 구간 막대(안에 "왼쪽"/"오른쪽"), "브레이크" 밟은 구간 막대.
  - 0초에 위험색 점선 세로줄 + 위에 "부딪힘".
  - `aligned: false`(시각 맞추기 coarse)면 그래프 아래 경고색 "영상과 차량 기록의 시각을 대략만 맞췄어요. 0초(부딪힘)가 실제와 몇 초 다를 수 있어요".
- 요약 카드 "기록 요약": 이름/값 행 — 속도("부딪힐 때 속도 23km/h · 이 구간 최고 43km/h"), 방향지시등("부딪히기 6.0초 전부터 왼쪽 지시등을 켜고 있었어요" / "부딪히기 전에 지시등을 켜지 않았어요"),
  브레이크("부딪히기 1.2초 전부터 브레이크를 밟았어요" / "부딪힌 뒤에 브레이크를 밟았어요" / "부딪히기 직전 3초 동안 브레이크를 밟지 않았어요"), 기어("D", 바뀌면 "D → R").
  아래 "결과에 미치는 영향": 결과 화면 카드와 같은 내용(바뀐 비율 "입증하면 …", 안내 문장, 기록 행), 맨 아래 상자 "참고 자료예요. 입증되면 결과가 바뀔 수 있어요".

### 2.8 여러 개 고르기 · 묶음 (2026-11-11)
질문 화면(2.4)과 같은 위 줄·아래 버튼. 본문은 그림 없이 전체 폭 카드 하나(넘치면 스크롤). 캡처 `docs/images/bb-multi-*.png`, `bb-bundle-ped-dark.png`.

**여러 개 고르기** (`type: multi`: `situation.special` 보기 약 80개, `parties.<ego|other>.driver_factors` 13개)
- 위 줄 "질문 6 / 8 · 선택 질문"(선택 질문일 때) + 서버 질문 문장. 카드 첫 줄 "해당하는 것을 모두 고르세요".
- 보기 칸: 체크 상자(48dp, 둥글기 12) + 글자, 최소 높이 80dp, 가로 창 2열·세로 창 1열. 고르면 강조색 4dp 테두리 + 옅은 파랑 바탕 + 채운 체크 상자.
  보기에 묶음 이름(`option_groups`)이 둘 넘게 있으면 묶음 이름 소제목 아래 묶음별로.
- 맨 아래 구분선 아래 한 줄 전체 "해당 없음"(보기 `none`의 서버 문구, 예: "해당 없음 (모두 아니요)"). 고르면 다른 보기가 모두 꺼지고, 다른 보기를 고르면 "해당 없음"이 꺼진다.
- 보내는 값 세 가지: 고른 보기 목록 `["speed_20plus","phone"]` / "건너뛰기" `[]`(답 없음, 영상·기본값으로) / "해당 없음" `["none"]`(전부 아니요).
  아무것도 안 고르면 "다음"이 꺼진다(건너뛰려면 "건너뛰기"). 왼쪽 글자 버튼은 "잘 모르겠어요" 대신 "건너뛰기".

**묶음** (보행자 가감 요소: `parties.other.vulnerable_type`·`road.protection_zone`·`road.ped_visibility`, 한 보기만 고르는 질문이지만 모두 "해당 없음" 보기가 있음)
- 이런 질문이 둘 넘게 이어지면 한 화면. 제목 "해당하는 것을 모두 고르세요", 카드 첫 줄 "질문마다 하나씩 고를 수 있어요. 고르지 않은 질문은 답하지 않은 것으로 보내요".
- 질문마다 굵은 질문 문장 + 추정 근거 + 보기 칸(그 질문의 "해당 없음" 보기는 뺌, 같은 질문 안에서는 하나만) + 차량 기록 참고 상자.
- 맨 아래 공통 "해당 없음" = 질문마다 그 질문의 해당 없음 값(`none`/`none`/`clear`)을 따로 보낸다. 다른 보기를 고르면 풀린다.
- 고르지 않은 질문은 답하지 않은 것(전에 했던 답도 뺌). "건너뛰기"는 묶음 질문 모두 답 없음.

### 2.9 사고 순간 고르기 (2026-11-13)
영상 다시 보기 화면(기기 원본 `content://`)의 고르기 모드. 캡처 `docs/images/ui-final-pick-*.png`.

- "후보" 줄: 서버 `candidates`마다 "18.2초" 작은 버튼 (누르면 그 순간으로 옮겨 멈춤).

  주의 상자 "과실비율이 나오면 서버의 영상이 지워져 다시 고를 수 없어요", 주 버튼 "이 순간으로 분석"(로딩), "다시 고르기". 뒤로 = 다시 고르기.

- 원본을 열 수 없으면 USB 아이콘 + "영상을 열 수 없어요. USB를 다시 연결해 주세요" + "다시 열기".
