# 앱 전체 흐름

> 2026-10-29 · 프론트·백엔드가 같이 보는 문서. 분석 API의 데이터 모양은 `docs/app_io.md`, 서버 구조는 `docs/backend.md`

## 1. 화면 구성

```
로그인 (카카오 / 구글)
 ├─ 과실비율 확인
 │    영상 올리기 → 모서리 찍기 → 분석(탐지·충돌) → 질문 ⇄ 답 (반복) → 결과 화면 (done)
 │                                                                   ├─ [내 보관함에 저장]
 │                                                                   └─ [이 사고 투표에 올리기]
 │                                                                       (done + 저장된 사건에서만 보임. 투표 글쓰기를 엶)
 ├─ 과실비율 투표
 │    목록 → 글 보기(영상·사고 설명) → 내 판단으로 투표 → 평균·분포·AI 결과 보기
 │    [글쓰기] → 내 보관함에서 분석이 끝난 사건 고르기 → 제목·설명 → 공개 범위·동의 → 올리기
 └─ 내 정보
      내 분석 기록 / 내가 올린 투표글 / 동의 관리 / 탈퇴
```

## 2. 로그인·회원가입

- 카카오·구글 소셜 로그인만 둔다. 비밀번호를 직접 저장하지 않는다
- 회원가입 = 첫 로그인 때 닉네임 정하기 + 약관 동의 (화면 하나)
  - 필수: 서비스 이용약관, 개인정보 처리방침
  - 선택: 학습 데이터 이용 동의 (6절). 안 해도 모든 기능을 똑같이 쓴다
- 서버는 소셜 로그인 정보로 회원을 만들고 앱에 로그인 토큰(JWT)을 준다
- 모바일 앱이라 로그인은 앱의 카카오·구글 SDK가 하고, 앱은 받은 토큰(카카오 access token / 구글 ID token)을 서버에 보낸다. 서버는 그 토큰을 카카오·구글에 확인한 뒤 우리 토큰(access + refresh)을 준다. 서버에 리디렉트 주소가 필요 없다
- 탈퇴하면 영상·분석 기록·투표글·학습용 사본을 다 지운다 (남긴 투표는 집계에서 빠짐)

## 3. 과실비율 확인 (분석)

지금까지 만든 흐름 그대로다 (`docs/app_io.md`).

1. 영상 종류 고르기 (CCTV / 블랙박스. 블랙박스는 아직 지원 안 함 안내)
2. 영상 올리기 → 서버가 바로 탐지 시작
3. 장소 종류 고르고 교차로 모서리 찍기 (탐지 중에 찍어도 됨)
4. 분석 → 질문 (영상으로 확실히 못 정한 것만, 답에 따라 판정이 바뀌는 것만)
5. 결과 화면
   - 과실비율, 도표 번호, 기본 비율, 적용된 수정요소
   - 근거: 충돌 장면 그림, 당사자 경로 그림, 사용자가 답한 내용
   - "영상 분석과 다르게 입력한 항목" (`answer_conflicts`)
   - 안내: 모서리 경고(`corner_notice`), 카메라 안내, 장 미지원 안내
   - **"법적 판단이 아닌 참고값"** 문구
6. 내 보관함에 저장 (안 하면 7일 뒤 자동 삭제, 7절)

## 4. 과실비율 투표

### 글쓰기

- 투표글은 분석과 따로 쓴다. 결과를 보고 나중에 올려도 되고, 안 올려도 된다
- 올릴 수 있는 것: **내 보관함에 저장한, 분석이 끝난(`done`) 사건**만. 저장 안 한 사건은 지워지기 때문
- 사건 하나에 투표글 하나 (같은 사고로 여러 번 못 올림)
- 결과 화면의 "이 사고 투표에 올리기"는 같은 글쓰기 화면을 그 사건이 골라진 채로 여는 바로가기다
  - **질문이 다 끝난 결과 화면(`done`)에서만** 보인다. 분석 중이거나 질문이 남았으면(`needs_answers`) 안 보인다. 그래서 투표 화면에 있는 동안 질문이 뜨는 일은 없다
  - 저장 안 한 사건이면 누를 때 먼저 보관함에 저장하고 글쓰기로 넘어간다
  - 선택 질문(특수 상황 등)은 답 안 해도 `done`이라, 올리기 전에 "해당하는 특수 상황이 있으면 먼저 알려 주세요"를 한 번 안내한다
  - 서버도 글을 만들 때 사건이 `done`이고 보관 중인지 확인하고, 아니면 거절한다
- 글은 올리는 순간의 결과·사고 설명을 **따로 저장한다(스냅샷)**. 그 뒤 보관함에서 답을 바꿔 다시 판정해도 투표글 내용은 그대로라, 투표 중에 사고 설명·AI 결과가 바뀌지 않는다
- 쓸 것: 제목, 설명(선택), 공개 범위
  - 공개 범위: 영상(흐림 처리, 8절) / 장면 그림만(충돌 장면 + 경로 그림)
  - 흐림 처리가 준비되기 전에는 "장면 그림만"으로 시작한다
- 올리기 전에 "다른 회원에게 공개됩니다" 동의를 받는다

### 투표

- 로그인한 회원만, 글 하나에 한 표. 글쓴이는 투표 못 함
- A:B 비율을 10% 단위로 고른다 (0:100 ~ 100:0). 투표를 바꿀 수 있다
- 글에 보여 주는 것: 영상(또는 장면 그림), 장소, 두 당사자 진행 방향 등 사고 설명 (사용자 답에서)
- **AI 결과는 투표한 뒤에 공개한다.** 먼저 보이면 AI 숫자를 따라 투표하게 돼서
- 투표 뒤: 평균 비율, 분포 막대, 투표 수, AI 결과와 근거

### 관리

- 글쓴이는 글을 지울 수 있다. 글을 지워도 분석 기록은 남는다
- 분석 기록을 지우면 연결된 투표글도 지워진다 (지우기 전에 알림)
- 신고 버튼. 신고가 쌓이면 숨김 처리하고 관리자가 확인

## 5. 내 정보

- 내 분석 기록 (보관함): 결과 다시 보기, 지우기
- 내가 올린 투표글: 현재 투표 결과, 지우기
- 동의 관리: 학습 데이터 이용 동의 켜기·끄기 (끄면 학습용 사본 삭제, 6절)
- 탈퇴

## 6. 학습 데이터 이용

사용자가 올린 영상과 답을 모델 학습에 쓰려면 아래를 지킨다. 사고 영상에는 얼굴·차량 번호가 찍혀 있어서 개인정보로 다뤄야 한다 (실제 서비스 전 법률 확인 필요).

- **별도 선택 동의**로 받는다. 필수 약관에 넣지 않는다. 동의서에 목적(모델 학습), 보관 기간, 철회 방법을 적는다
- 영상 속 다른 사람(상대 운전자, 보행자, 다른 차 번호)은 동의한 적이 없으므로, **얼굴·번호판을 흐리게 처리한 사본만** 학습용으로 남긴다
- 학습용 사본은 서비스용 영상과 저장 위치·보관 기간을 나눈다
- 동의 철회·탈퇴 시 학습용 사본을 지운다 (이미 학습된 모델은 그대로, 다음 학습부터 뺌)
- 정보공개 청구로 받은 CCTV처럼 이용 목적이 정해진 영상이 있을 수 있어서, "본인이 이용 권한을 가진 영상만" 동의하도록 안내한다
- **사용자 답과 고친 모서리는 라벨이 된다** (진행 방향, 진입 순서, 신호 색, 당사자 종류, 교차로 모서리). 단 당사자는 자기에게 유리하게 답할 수 있어서, 모델 추정과 같은 답이나 팀이 다시 확인한 것 위주로 쓴다

## 7. 저장과 보관 기간

| 상태 | 영상 | 분석 결과 |
|---|---|---|
| 분석만 하고 저장 안 함 | 7일 뒤 자동 삭제 | 같이 삭제 |
| 내 보관함에 저장 | 사고 구간만 압축한 영상 보관 (원본은 분석 후 삭제) | 보관 |
| 투표에 올림 | 공개 범위에 따라 흐림 처리 영상 또는 장면 그림 공개 | 공개용 요약만 (사용자 답 중 사고 설명) |
| 학습 동의 | 흐림 처리 사본을 학습용 저장소에 따로 | 답·모서리를 라벨로 |

- 어림 크기: 사고 구간 720p 압축 영상 2~10MB + 분석 결과 1~2MB. 투표글 1,000개면 약 10GB
- 저장보다 분석(탐지 30~60초, CPU)이 훨씬 무겁다. 작업자 구조로 줄을 세운다 (`backend.md` 4절)
- 처음에는 서버 디스크, 커지면 영상만 S3 같은 저장소로 옮긴다

## 8. 개인정보

- 투표 공개 영상과 학습용 사본은 얼굴·번호판을 흐리게 처리한다 (탐지에 번호판·얼굴 탐지를 더함)
- 사건·글 id는 추측할 수 없는 UUID
- 서버 기록(log)에 영상 이름·답 내용을 남기지 않는다
- 올릴 수 있는 크기·길이 제한 (예: 200MB, 60초)

## 9. 데이터 표

| 표 | 주요 칸 |
|---|---|
| `users` | id, 소셜 종류(kakao/google), 소셜 id, 닉네임, 가입 시각, 약관 동의 시각, 학습 동의 시각 (회원 단위, 끄면 비움) |
| `cases` | id, 주인(user), 상태(`app_io.md` 3.1 + 서버 상태), 진행률, 보관 여부, 만든 시각, 삭제 예정 시각. 결과(`app.json`)·답은 사건 폴더 파일 |
| `sessions` | refresh 토큰 id, 회원, 만료 시각 (로그아웃·재발급 때 지움) |
| `posts` | id, 사건(case, 하나에 하나), 글쓴이, 제목, 설명, 공개 범위(video/frames), 올릴 때의 결과·사고 설명 스냅샷, 상태(공개/숨김/삭제), 만든 시각 |
| `votes` | 글(post), 회원(user), A 비율(0~100, 10 단위), 시각. (글, 회원)은 하나만 |
| `reports` | 글, 신고한 회원, 이유, 시각 |
| `jobs` | 사건, 종류(prepare/solve/answer), 상태 (분석 작업 줄, `backend.md` 4절) |
