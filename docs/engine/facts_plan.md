# 차대차 마무리: A가 채울 사실 계획

> 2026-10-27 · B는 차대차 도표(v0.13.x, 124개)를 다 매핑했다. 이제 판정 범위를 막는 건 A가 주는 사실이다.

## 1. 지금 상태

- 도표 124개가 조건으로 쓰는 사실 61가지 중 **A가 채우는 건 13가지**(진행 방향, 진입로, 종류, 신호 색, 진입 시각·순서, 도로 폭, 중앙선, 진입 전 정지 등)
- 판정 엔진은 사실이 비면 그 도표를 **보류**하고, 조건이 다 맞는 다른 도표가 있으면 그중에서 고른다 (`fault_engine.judge`). 그래서 사실이 비면:
  1. 맞는 도표가 없으면 "규칙 없음" (180304, 200507은 `lead_order`가 없어서)
  2. 더 맞는 특수 도표가 보류된 채 **일반 도표로 조용히 판정됨.** 예: `stop_sign`이 비어 있으면 일시정지 표지 교차로(차7~10)는 보류되고 신호 없는 교차로(차12)로 판정되며, 차12에는 "확인 필요: 한쪽에 일시정지 표지가 있으면 차7~10 적용"이 붙는다. 지금까지 차12 판정은 모두 이 상태였다

## 1-1. 진행 상황 (10-27, 1차 묶음)

| 사실 | 상태 |
|---|---|
| `lead_order`, `side_in_pair` | 궤적(`build_facts.pair_motion`): 충돌 직전 두 진행 방향 차이가 45도 안이면 진행 방향 축으로 앞뒤, 옆 방향으로 좌우. 서 있던 차는 멈추기 전 방향으로 보고, 처음부터 서 있던 차를 같은 줄 뒤에서 들이받은 모양이면 추돌로 앞뒤를 정함. 직접 표시한 당사자는 궤적을 안 믿고 질문. 궤적으로 못 정하면 같은 길에서 왔을 때 질문(`pair.lead_order`) |
| `stop_state` | 충돌 직전 움직였으면 `driving`. 서 있었으면 같은 방향 사고일 때만 이유를 물음 |
| `started_after_stop` | 궤적: 충돌 3초 안에 5프레임 넘게 멈췄다가 다시 움직임 |
| `stop_sign` | 질문 `road.stop_sign_side` (신호등 없음이라고 답했을 때). 기본값 "없음" → 차12 판정에 늘 붙던 "확인 필요: 일시정지 표지" 사라짐 |
| `unprotected_left_sign`, `u_turn_type`, `scene.lane_fits_two` | 질문 (좌회전 당사자 + 신호 / 유턴 당사자 / 같은 방향 + 회전) |
| 보행자·자전거 사고 | 차대차 상황 질문을 안 함 |

판정이 갈리지 않는 질문은 지운다(`situation.DROP_IF_SAME`). 앞차·서 있던 이유는 빼는데, 이 답이 있어야 다음 질문(차로 폭)이 생겨서 혼자서는 판정을 못 바꾸기 때문이다.

평가 결과: 판정 변화 없음 (24/24, 7/24). 200507(같은 방향 좌회전 대 뒤차 직진)은 "규칙 없음"이었는데 이제 앞차(5번) → 차로 폭 "넓었음"으로 답하면 **차19-1 68번 20 : 5번 80** (정답 30 : 70). 차로 폭 실제 답은 장면으로 확인 전이라 평가 답에는 아직 안 넣음. 180304는 이륜차의 들어온 길 답이 비어 있어 앞차 질문이 안 뜸 (앞차를 68번으로 넣으면 차41-1, 정답과 다름).

### 10-27 추가

- **선진입**: B의 `clear_lead_sec`(1초)는 임시값이다. A는 "먼저 들어감" 답을 무조건 1초로 올려 보내서 B 기준에 늘 걸리게 하고 있었다. 이제 순서를 답으로 받았으면(측정을 못 믿을 때만 묻는 질문) "확실히 먼저였나요?"(`intersection_entry_clear`)를 따로 묻고, 확실하면 B의 `clear_lead_sec`, 아니거나 답이 없으면 그 절반을 넘긴다. 기준 숫자는 B의 rules.json에서 읽어서(`judge_bridge.thresholds`) B가 바꾸면 따라간다. A가 확실하게 잰 진입 시각 차이(211217의 2초)는 그대로 B로 간다. **180629가 정답과 같아져 답 반영 비율 7/24 → 8/24**
- **특수 상황**: `situation.special` 한 질문(여러 개 고르기, 선택 질문). 긴급자동차·일방통행 역주행·문 열림·짐 떨어짐·버스정류장 출발(당사자별), 고속도로. 답하면 고른 것은 true, 안 고른 것은 false로 넘겨서 차41의 "적재물 낙하면 차48" 같은 제외 조건도 풀림

### 10-27 2차 묶음

있었다/없었다로 끝나는 사실은 **특수 상황 질문(선택, 여러 개 고르기)에 상황별 보기로** 넣고, 값이 여러 개인 사실만 앞 답에 따라 따로 묻는다. 질문 수를 늘리지 않으려는 것.

| 사실 | 받는 방법 | 도표 |
|---|---|---|
| 진로 변경, 후진 (`movement: lane_change / reverse`) | 진행 방향 보기에 추가 + 특수 상황 "차로를 바꾸던 중", "후진하던 중" | 차43, 47, 31-4 |
| `lane_change_dir` | 진로 변경이면 "어느 쪽 차로로" | 차43-3 |
| `cut_in`, `from_congested_lane`, `merging`, `lane_change_first` | 특수 상황 (같은 방향 사고일 때 보기) | 차20-2, 43 |
| `overtake_type` | 특수 상황 "앞지르기 하던 중" → 유형 7가지 | 차45, 47-1 |
| `crossed_center_line`, `wrong_way` | 특수 상황 (마주 오는 사고일 때 보기, 궤적 `opposite_direction`) | 차31 |
| `from_off_road` | 특수 상황 (늘) | 차31-2, 44-1 |
| `lane_change_in_intersection` | 특수 상황 (교차로 + 직진 당사자) | 차13-2 |
| `u_turn_timing` | 두 차 다 유턴이면 질문 | 차46-1 |
| `ped_signal_green_at_turn` | 신호 교차로 + 우회전 당사자 질문 | 차5-2 |
| `lane_marking` | 교차로면 당사자별 선택 질문 (두 차 다 있어야 차11이 골라져서 "판정 안 갈리면 지우기"를 안 씀) | 차11 |
| `scene.center_line_rule_not_applied` | 마주 오는 사고 + 중앙선 있음 | 차32-1 |
| `scene.location` (교차로 / 벗어난 길) | 충돌이 교차로 영역 밖에서 났을 때만 질문. 영역만 보고 바꾸지 않음 (191207은 진입로 영역인데 교차로 도표로 정답) | 차31, 32 (교차로가 아닌 곳) |

- 장소는 판정용 facts에서 비우고 가정으로 넘긴다 (B adapter가 facts 값을 먼저 써서 답이 무시됐음)
- 확인: `tests/test_rules_coverage.py`에서 A 형식 facts + 답을 B 엔진에 넣어 차7-1, 41-1, 43-2, 31-1, 45-1, 46-1(가), 11-3이 골라지는 것을 봄. 평가 판정 변화 없음

### 10-27 3차: 범위 밖 장소와 나머지 사실 (질문으로)

영상으로 회전 차로·주차 칸·갓길을 알아볼 수 없어도, 사용자는 안다. 그래서 **장소 종류는 모서리 찍는 단계에서 고르고**(`--place`, 서버는 `PUT scene`의 `place`), 그 장소의 도표에 필요한 것은 질문으로 받는다. 이로써 이 계획표에 적은 사실은 모두 넘긴다.

| 사실 | 받는 방법 | 도표 |
|---|---|---|
| `scene.location` = `roundabout` / `parking_lot` / `straight` | 모서리 단계에서 장소 종류 고르기 (기본 `intersection`). 모서리 네 개는 그대로 찍음 (그 장소의 중심 영역) | 차51, 54, 31·32 |
| `scene.roundabout_lanes` | 회전교차로면 "회전 차로는 몇 개였나요?" (1개 / 2개 이상) | 차54 |
| `roundabout_action` | 회전교차로면 당사자별 "돌고 있었음 / 들어오던 중 / 바깥 차로로 바꿔 나가던 중" | 차54 |
| `roundabout_lane`, `entry_lane_from`, `big_entry` | 회전 차로가 2개 이상일 때만: 돌던·들어간 회전 차로, 들어오기 전 차로, 1차로로 크게 들어갔는지 | 차54-2~5 |
| `in_parking_aisle`, `leaving_parking_space`, `entering_parking_space` | 주차장이면 당사자별 "통로를 달림 / 칸에서 나옴 / 칸으로 들어감" 하나 → 셋 중 하나만 true. 칸으로 들어감 + 통로면 앞차 질문 | 차51 |
| `against_parking_arrow` | 주차장이면 특수 상황 보기 | 수정요소 |
| `road.center_line` | 교차로 아닌 길이면 중앙선 질문 (교차로는 build_facts가 물음) | 차31, 32 |
| `position` | 서 있던 이유가 주정차·앞선 사고이면 "서 있던 곳"(차로 안 / 갓길 / 도로 가장자리). 상대가 갓길로 차로를 바꿨으면 이쪽이 "달리던 곳" | 차42-2·3, 43-6 |
| `to_shoulder`, `through_safety_zone` | 특수 상황 보기 (같은 방향) | 차43-6, 43-7 |
| `in_safety_zone_at_collision` | 안전지대를 골랐으면 "부딪힐 때 아직 안이었나요?" | 차43-7(가)/(나) |
| `driving_left_side`, `overtaking` | 긴급자동차를 골랐으면 "어떻게 달리고 있었나요?" (보통 / 가운데·왼쪽 / 앞지르던 중) | 차55-2·3·5 |
| `between_congested_queue`, `on_sidewalk`, `passing_on_right` | 특수 상황 보기. **그 당사자가 이륜차일 때만** 보기에 나옴 | 차61 |
| `to_off_road` | 특수 상황 보기 (늘) | 차61-2 |

- 회전교차로·주차장 질문은 "판정 안 갈리면 지우기"를 쓰지 않는다. 두 당사자 답이 다 있어야 도표가 골라져서 하나만 바꿔 보면 늘 같기 때문
- 확인: `tests/test_rules_coverage.py`에 차54-1~5, 51-1·2, 42-2·3, 43-6, 43-7(가)(나), 55-2·5, 61-1·3 추가. 테스트에 넣은 답이 모두 앱이 실제로 묻는 질문인지도 검사함. 평가 판정 변화 없음 (평가 영상은 모두 교차로)

## 2. 채우는 방법 세 가지

- **궤적으로 잼**: 두 차의 위치·방향·속도만으로 정할 수 있는 것. 애매하면 질문으로 확인 (진행 방향처럼)
- **질문**: 표지판·도로 성격처럼 영상으로 보기 어렵거나 사용자가 바로 아는 것. 신호등 유무처럼 **판정이 갈릴 때만** 묻는다
- **이번 범위 밖**: 회전교차로·주차장처럼 장면 모양부터 다르거나, 차선 인식이 있어야 하는 것. B에게 "아직 안 받는 사실"로 알리고 도표는 그대로 둔다

### 특수 상황 질문 하나로 묶기

드문 특수 도표는 사실마다 묻지 않고 **"해당하는 것이 있나요?" 한 질문(여러 개 고르기)**으로 받는다. 대부분 "없음"이라 사용자는 한 번만 누르면 된다.

| 보기 | 사실 | 도표 |
|---|---|---|
| 긴급자동차(경광등·사이렌)였음 | `is_emergency` | 차55 (7개, 우선 적용) |
| 일방통행을 거꾸로 들어감 | `one_way_violation` | 차7-2 |
| 정차한 차 문이 열림 | `door_opening` | 차52-1, 61-3 |
| 앞차 짐이 떨어짐 | `dropped_cargo` | 차48-1 |
| 버스가 정류장에서 출발 | `at_bus_stop` | 차47-3 |
| 고속도로·자동차전용도로 | `road.road_type` = `highway` | 차42-3 등 |

## 4. 질문은 "판정이 갈릴 때만"

질문이 늘면 사용자가 지친다. 중앙선·도로 폭과 같은 방법으로, **답에 따라 판정이 갈리지 않는 질문은 지운다.** 예: 두 차가 직진·직진이면 `u_turn_type`, `unprotected_left_sign`은 묻지 않는다. `stop_sign`은 신호 없는 교차로에서만 묻는다.

### 7.1 신호등 (11-02, `src/app/signals.py`)

판정에 필요한 건 "1번 차가 들어갈 때 **1번 차 쪽** 신호"인데, 탐지 모델은 화면의 신호등이 어느 길의 신호인지 모른다 (CCTV는 신호등 옆·뒤를 찍는 경우도 많음). 그래서 사실을 셋으로 나눈다.

| 사실 | 채우는 법 |
|---|---|
| 교차로에 신호등이 있나 | 늘 질문 (화면에 안 보여도 화면 밖에 있을 수 있음) |
| 신호등 ↔ 진입로 | 신호등이 있다고 답하면, 색 기록이 5개 이상인 신호등(많은 순 4개)마다 "N번 신호등은 어느 길의 신호인가요?" (선택 질문). 그림은 진입로 이름 + 신호등 확대 (`frames.light_image`) |
| 그 신호등의 색 | 연결된 신호등의 프레임별 색으로 당사자 진입 때·충돌 때 색을 추정 |

모델 값의 확신도에 따라 세 갈래:

| 확신 | 처리 |
|---|---|
| 높음 (`MTM_SIGNAL_AUTO_MIN` 이상) | 질문 없이 사실로 (`verdict.auto_facts`). 지금 분류기(0.70)로는 끔. B 모델 정확도를 보고 켬 |
| 애매 | 신호 색 질문에 추정값을 미리 골라 둠 (`model_guess`, 답이 없으면 그 값으로 판정) |
| 모름 | 빈 질문 |

추정을 안 하는 경우: 근처(±6프레임) 기록의 확신이 0.6 미만, 같은 색 비율 0.75 미만(색이 바뀌는 순간), etc(노랑·꺼짐 구분 못 함), 같은 길에 연결한 신호등끼리 색이 다름(화살표 신호 등). 빨강 점멸은 앞뒤 30프레임에서 빨강↔etc가 4번 이상 바뀌면. 노랑 점멸은 지금 분류기로 못 가려 질문.

B 모델이 오면: 색 클래스(빨강·초록·노랑·꺼짐·좌회전 화살표)와 클래스별 정확도를 받아 `light_states`를 바꾸고, 정확도를 보고 `MTM_SIGNAL_AUTO_MIN`을 정한다. 연결 질문은 그대로 필요하다.

### 8.1 서행 (11-02, `src/app/slowdown.py`)

평가 24개(당사자 48명)에서 진입 직전 감속을 재 봄 (`tools/experiments/slowdown_try.py`): 잴 수 있던 건 18명(38%, 나머지는 진입이 안 보이거나 진입 전 궤적이 2초 미만). 감속 비율(진입 직전 1초 최저 속도 ÷ 그 전 1초)은 대부분 0.4~1.1이고, 회전하는 차는 원래 속도를 줄여서 비율로는 못 가름. AI Hub 라벨에 서행 정보가 없어 기준값도 못 맞춤. 211208 1번 차는 0.43으로 꽤 줄였지만 정답 비율에 서행 감산이 없었음.

그래서 확실한 두 경우만 추정하고 나머지는 질문:

| 경우 | 처리 |
|---|---|
| 진입 전에 멈춤 (`stopped_before_entry`, 경계 검사 통과) | 줄였음. 질문 안 함 (판정 모듈이 멈춤을 서행으로 봄) |
| 진입 직전에 오히려 빨라짐 (비율 1.1 이상) | "안 줄였음"을 미리 골라 둔 질문 |
| 나머지 | 빈 질문 |

질문 `parties.<id>.slowed_before_entry`는 비신호 교차로(신호등 없음이라고 답함)에서 두 당사자에게, 판정이 같으면 지움. 평가 24개 다시 판정: 비율 일치 8/24 그대로, 서행 질문이 남은 영상 6개(10개 질문).

### 7.2 신호등 유무 추정은 안 함 (11-02)

"신호등이 화면에 보이면 '있음'을 미리 골라 두기"를 보려고 평가 영상의 신호등 탐지를 셌더니, **신호등이 없는 교차로 24개 중 8개에서도 색이 잡힌 신호등이 나옴** (150101은 4개, 190510·210224·210814도 4개). 근처 다른 교차로 신호등, 점멸 신호, 보행자 신호로 보임. 미리 고르면 비신호 사고를 신호 도표로 잘못 보낼 수 있어서, 신호등 유무는 지금처럼 늘 빈 질문으로 둠.

### 7.3 적신호 직전 진입 (11-02)

신호등이 있다고 답하면 특수 상황에 "N번이 노란불에 들어가서 곧 빨간불이 됨"(`entered_just_before_red`, +10)이 생김. 신호등을 연결했고, 진입 때 색이 빨강이 아니었는데 진입 뒤 2초 안에 빨강이 되면 그 보기를 미리 골라 둠 (`signals.late_red`). 색 분류기가 노랑을 따로 못 가려서 "곧 빨강이 됨"으로 대신 봄.
